本手册保留迭代 01 四项 Project 任务的验收步骤，并作为后续迭代的回归基线。主环境为 Windows 10/11 的非管理员用户。测试记录应写明 commit、Node/包管理器/Rust/Python/Windows 版本、执行命令、退出码、实际结果和问题链接。可执行命令见仓库及工程 README；实际结果见 [复核记录](04-verification.md)。

**截至 2026-09-29：** 自动检查为后端 23 passed、1 skipped，Rust 健康测试 4 passed，前端与 Tauri 生产构建通过。用户报告安装后窗口可运行；尚无健康按钮返回值、后端不可用及超时路径的逐项人工记录。不能将这些未记录项写成“已通过”。

所有自动测试均使用临时应用数据目录，不访问真实用户 DB，不需要网络或模型密钥。测试目录仅能清理自己创建的路径。

## T01 桌面开发与生产启动（任务 1）

1. 全新克隆，按 README 安装锁定依赖并运行前端类型检查。
2. 运行 Tauri 开发命令，确认 Windows 窗口出现，React 根视图显示 MindFlip 内容。
3. 执行生产桌面构建，从产物启动并重复观察。

**预期：** 所有命令退出码为 0；开发和生产窗口都能渲染 React。记录生产产物路径与启动方式。不要把仅生成前端静态文件当作 Tauri 生产构建成功。

## T02 后端独立启动（任务 2）

1. 不启动 Tauri，按 README 独立启动 Python 后端。
2. 连续调用健康服务至少两次，比较响应；执行健康单元测试。
3. 在未配置模型密钥和无 DB 的测试目录重复。

**预期：** 健康响应均为同一确定性 OK 结构；后端清晰退出；无供应商 API 调用或数据库依赖。

## T03 健康链路与异常（任务 3）

1. 启动完整桌面，点击 UI 的健康检查入口，记录请求与 UI 响应。
2. 由于当前实现为每次请求新建 Python 进程，验证“不可用”应在启动桌面前暂时把当前 PowerShell 会话的 `MINDFLIP_PYTHON` 指向一个不存在的可执行路径，再从该会话启动 `tauri dev`；不要修改持久用户环境变量。
3. 超时路径使用专门的测试后端或自动化桩，在收到请求后延迟超过 Rust 的 3 秒超时；恢复正常解释器后重试。不要改动正式 Python 入口来制造延迟。
4. 在集成测试中校验请求/响应 schema、相同 `request_id`、未知方法和无效载荷。

**预期：** 成功响应真实来自 Python；不可用与超时分别显示稳定错误状态和重试入口；恢复后可成功；无白屏、无限等待或原始异常栈。React feature 组件只调用 `src/api` 封装。

## T04 SQLite 迁移与持久化（任务 4）

1. 将应用数据位置注入临时空目录，执行 Alembic upgrade，检查 DB 和版本表。
2. 通过持久化层插入测试值并提交；关闭 engine，重新打开后查询。
3. 再次启动/升级，确认已有值仍在且未重复创建 schema。
4. 触发一次事务失败，确认回滚；尝试不可写目录，检查可诊断错误。

**预期：** DB 仅在指定应用数据目录；初始迁移成功；重开值不丢失；重复启动不清库；失败不产生半提交数据。UI 与 transport 层没有 SQL。
